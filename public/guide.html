How an X12 834 file is structured

An 834 file is plain text made of segments, each ending in a tilde (~), the segment terminator. Inside a segment, individual elements are separated by an asterisk (*), the element separator. The first element is always the segment's tag — ISA, NM1, HD, and so on — which tells you what kind of data follows.

NM1*IL*1*Doe*Jane****34*123456789~

Segments are grouped into loops — repeating blocks that describe one logical thing, like one member or one coverage. This app's Editor Settings let you toggle whether each segment gets its own line, and whether long segments wrap — that's purely cosmetic and has zero effect on the underlying data or on other systems reading the file.

Note: this app implements a practical, simplified subset of the real X12 834 (005010X220A1) implementation guide — enough to model members, dependents, coverages, payments, providers, coordination of benefits, and reporting categories with correct segment structure. It is not a certified/complete implementation of every loop in the full spec.

ISA — Interchange Control Header

The very first segment of any X12 file. Identifies who sent the interchange and who it's addressed to, using fixed-width sender/receiver IDs. Maps to the Sender ID / Receiver ID / Control Number fields in the Header section of the form.

ISA*00* *00* *ZZ*SENDERID *ZZ*RECEIVERID *260803*1200*^*00501*000000001*0*T*:~

ISA06Sender IDSENDERIDSpace-padded to 15 characters

ISA15Usage IndicatorTT = test, P = production

GS — Functional Group Header

Wraps one or more transaction sets of the same type (here, always 834s) inside the interchange. 005010X220A1 identifies this as the 834 Benefit Enrollment and Maintenance implementation guide version.

GS*BE*SENDERID*RECEIVERID*20260803*1200*1*X*005010X220A1~

ST / BGN — Transaction Set Start

ST marks the start of one 834 transaction (834 = Benefit Enrollment and Maintenance). BGN gives it a reference number and a creation date/time — this reuses the same Control Number field as the header.

ST*834*0001~ BGN*00*1*20260803*1200***4~

N1 — Sponsor & Payer (Loop 1000A / 1000B)

Two N1 segments identify the parties in this exchange: P5 is the Sponsor (the employer or plan sponsor), and IN is the Insurer/Payer (who administers the coverage). Both map directly to the Header (Loop 1000A / 1000B) section of the form.

N1*P5*Acme Corp*FI*123456789~ N1*IN*Blue Shield Health Plan*FI*987654321~

INS — Member Level Detail (Loop 2000)

Opens a new person's record — either the subscriber (member) or one of their dependents. INS02 is the Relationship Code (18=Self, 01=Spouse, 19=Child, etc.), INS03 is the Maintenance Type Code (021=Addition, 001=Change, 024=Termination, ...). INS01 is Y for the subscriber and N for every dependent — that single flag is what tells the parser (and this app) where one person's Loop 2000 ends and the next one begins.

INS*Y*18*021*AI***FT~

DTP*007 — Maintenance Effective Date

Immediately follows INS. Qualifier 007 = "Effective Date" — the date this specific maintenance action (the addition, change, or termination named in INS03) actually takes effect. This is distinct from the DTP*348/ DTP*349 coverage start/end dates further down in Loop 2300 — this one is about the enrollment transaction, not the coverage period. Only emitted when a value is entered.

DTP*007*D8*20260101~

REF*0F — Subscriber/Member ID

The qualifier 0F means "this REF is a member/subscriber identification number." Maps to Member ID on the form.

REF*0F*MBR1002345~

REF — Additional References

Any number of extra REF segments can follow REF*0F for identifiers that don't fit the other qualifiers — a group number (1L), case number (3H), client number (23), and so on. Add as many as needed in the "Additional References" section of the Member card; each becomes one REF line. On parse, any REF at the member level that isn't 0F and isn't already inside a coverage or reporting-category context is treated as one of these.

REF*1L*GRP4021~ REF*3H*CASE9981~

NM1*IL — Member Name

IL identifies this as the "Insured or Subscriber" name segment. 34 in position 8 is the ID qualifier for a Social Security Number, with the SSN itself in position 9.

NM1*IL*1*Doe*Jane*A***34*123456789~

DMG — Demographics

Date of birth (format D8 = CCYYMMDD) and gender (M/F/U).

DMG*D8*19850612*F~

N3 / N4 — Address

N3 carries the street address, N4 carries city, state, and ZIP.

N3*123 Main Street~ N4*Springfield*IL*62704~

Mailing Address — Loop 2100C

A second address, used when mail should go somewhere different from the residential address above (a PO box, a relative's address, etc.). It's its own mini-loop: an NM1*31 segment (entity type 2, no name — it exists purely to mark "the next N3/N4 pair is the mailing address") followed by one N3/N4 pair. Only emitted if at least one mailing-address field is filled in on the form.

NM1*31*2~ N3*PO Box 500~ N4*Chicago*IL*60601~

Responsible Party — Loop 2100F

Names a guardian or other financially-responsible person distinct from the member — common for minors or dependents who aren't the policyholder. Qualifier GD identifies the entity as the responsible party; its name comes right in the NM1 segment, followed by its own N3/N4 address pair. Only emitted if a name or address is entered.

NM1*GD*1*Doe*John~ N3*789 Elm St~ N4*Aurora*IL*60502~

PER*IP — Member Contact Info

The member's own phone and/or email — qualifier IP distinguishes this from the provider's contact segment in Loop 2310 (which uses IC). Only the pairs that are actually filled in get emitted, so the position of EM/email shifts depending on whether a phone number precedes it — the parser scans for TE/EM qualifiers rather than assuming fixed positions.

PER*IP**TE*3125551234*EM*jane@example.com~

Email only, no phone: PER*IP**EM*jane@example.com~

Languages — Speak / Write / Read

Three fixed slots, one per proficiency type, each its own LUI segment: LUI01 is always LE (Language), LUI02 is the language code, LUI03 is left blank, and LUI04 carries a proficiency number — 5 = Speak, 6 = Write, 7 = Read. On the form this is one compact row: a checkbox and a small language dropdown per slot. A slot's LUI line is only emitted while its checkbox is checked (i.e. its code is non-empty).

LUI*LE*ENG**5~ LUI*LE*ENG**6~ LUI*LE*ENG**7~

Dependents — a nested Loop 2000

Each dependent is its own complete Loop 2000 (INS/REF/NM1/DMG/N3/N4/coverages), placed right after the subscriber's. The only structural difference is INS01 = N and a dependent relationship code such as 19 (Child).

INS*N*19*021*AI***FT~ REF*0F*~ NM1*IL*1*Doe*Sam****34*~ DMG*D8**U~ N3*~ N4***~

HD — Health Coverage (Loop 2300)

One HD segment per coverage a member has. HD01 is the maintenance type, HD03 is the Insurance Line Code (comes from the LOB rule's X12 code in LOB Mapping Settings — e.g. HLT for Medical), HD04 is a free-text plan description, and HD05 is the Coverage Level (IND=Individual, FAM=Family, ...).

HD*021**HLT*Medical*IND~

DTP — Coverage Dates

Qualifier 348 is the coverage Start Date, 349 is the End Date. Both use format D8 and are only emitted when the form field is actually filled in.

DTP*348*D8*20260101~ DTP*349*D8*20261231~

REF — Custom LOB Reference

If a Line of Business rule (see LOB Mapping Settings) has "custom REF segment" enabled, its qualifier and the coverage's Reference Value produce one more REF line here — e.g. a group or class-of-contract number.

REF*CE*GRP4488~

REF*18 — HIOS Plan ID

For ACA Health Insurance Marketplace enrollments, plans are identified by a CMS-issued HIOS ID (a 14-character code like 12345OH1234567 — issuer ID + product/plan variant). Qualifier 18 ("Plan Number") carries it. This is independent of the LOB rule's own custom REF above — a coverage can have both.

REF*18*12345OH1234567~

AMT — Premium Amount

Qualifier P5 = premium amount. Only emitted when a Premium Amount is entered on the coverage. Maps to the "Payment (AMT)" section of the coverage card.

AMT*P5*425.50~

Provider — Loop 2310

Only emitted when a Provider Name or NPI is entered. LX is just a loop counter. NM1*P3 identifies the Primary Care Provider — entity type 2 means "organization" (a single combined name field, no first/last split), and qualifier XX in position 8 means "the next value is an NPI." PER carries a phone number (qualifier TE) if one was entered.

LX*1~ NM1*P3*2*Dr Smith Family Clinic*****XX*1234567890~ PER*IC**TE*3125551234~

Coordination of Benefits — Loop 2320/2330

Only emitted when a Payer Responsibility code or Other Payer Name is entered. COB01 is the Payer Responsibility Sequence (P=Primary, S=Secondary, T=Tertiary). The following NM1*IN names the other payer, with qualifier PI for its payer ID.

COB*S~ NM1*IN*2*Other Health Plan Inc*****PI*OP99887~

Reporting Categories — Loop 2700/2750

A member-level loop for payer-defined reporting buckets (division, union, class, ...), only emitted if at least one Reporting Category was added. LS*2700 / LE*2700 bracket the whole loop. Each category starts with its own LX assigned number (1, 2, ... — restarting at 1 for each member), followed by N1*75 (description) and a REF (qualifier + value), and optionally ends with a DTP*007 effective date for that specific category — only emitted if a date was entered. On the form this whole loop is one compact editable table: Description / Qualifier / Value / Effective Date per row.

LS*2700~ LX*1~ N1*75*Division~ REF*17*WEST~ DTP*007*D8*20260101~ LX*2~ N1*75*Union Code~ REF*ZZ*LOCAL42~ LE*2700~

SE / GE / IEA — Trailers

Every envelope segment gets a matching trailer that closes it out and states a count, so a receiver can verify nothing was truncated in transit. SE01 is the total segment count from ST through SE inclusive; GE/IEA control numbers must match their opening GS/ISA.

SE*22*0001~ GE*1*1~ IEA*1*000000001~
